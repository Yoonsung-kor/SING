# AI 활용 계획

기준일: 2026-10-13. **이 문서는 계획이다. 현재 앱에는 생성형 AI 호출이나 학습 모델이 연결되어 있지 않다.**

## 측정과 설명의 역할

프로젝트에서 확인하려는 것은 ‘목표 음정이 맞는지’와 ‘음을 유지하는 동안 음높이가 얼마나 변하는지’다. 이를 발표에서는 **음정 정확도·음높이 유지 안정성 분석**으로 표현한다. 악센트나 음색 측정은 현재 범위와 다르다.

현재 `pitch.js`가 단일 음의 주기성을 분석해 주파수와 음이름을 추정한다. 음높이 변화 관련 임계값은 신뢰도 판정에 사용하지만, 사용자가 볼 수 있는 시간별 변화 그래프나 별도의 안정성 점수는 아직 제공하지 않는다.

먼저 앱이 수치를 계산하고 실제 기기에서 검증한다. 생성형 AI는 이 수치와 체감을 근거로 결과를 설명하고 다음 과제를 제안하는 역할을 맡길 계획이다.

## 기능별 입력 → 처리 → 출력

| 기능 | 입력 | 처리와 AI의 역할 | 출력 | 선행 조건 |
| --- | --- | --- | --- | --- |
| 연습 피드백 | 목표음, 유효 구간의 음높이 변화, 목표와의 차이, 유지 시간, 측정 신뢰도, 체감 | 분석 코드가 수치를 계산하고 생성형 AI가 관찰 내용을 설명 | 이번 시도 요약, 확인할 점, 다음 행동 | 지표 정의와 Android 녹음 검증 |
| 맞춤 연습 | 최근 결과, 목표, 가능한 시간, 준비된 연습 목록 | 조건에 맞는 과제를 제한한 뒤 AI가 선택 이유 설명 | 추천 과제와 시간, 선택 이유 | 연습 콘텐츠와 진행/중단 규칙 검토 |

| 주간 변화 요약 | 같은 과제의 누적 지표와 체감 | 비교 가능한 기록을 묶고 AI가 변화를 설명 | 이번 주 변화와 다음 목표 | 반복 기록과 비교 기준 |

## 첫 AI 기능의 범위

1. 짧은 한 음 연습을 대상으로 목표음과의 차이, 음높이 변화, 유효 음성 길이와 신뢰도를 정의한다.
2. 낮은 신뢰도와 누락값을 성공이나 0점으로 처리하지 않는다. 사용자 체감은 별도 필드로 유지한다.
3. 이 구조화된 결과만으로 짧은 피드백을 생성하는 기능부터 연결한다.
4. 다음 과제는 검토된 콘텐츠 목록 안에서 선택하게 한다.
5. API 실패·응답 오류 시에는 측정 사실에 기반한 기본 안내를 제공한다.

음높이가 흔들렸다는 사실만으로 호흡·성대·발성 습관의 원인을 단정하지 않는다. 점수·수치·존재하지 않는 곡 정보를 모델이 만들어내지 않도록 응답을 검증한다.

## 데이터와 시스템 설계 예정

- API 키는 추가할 서버에서 관리한다. 브라우저 코드에 넣지 않는다.
- 초기 연결은 원음보다 측정 지표와 필요한 이력을 중심으로 설계한다.
- 외부 전송 항목과 사용 목적은 연결 전에 화면에서 안내하고 동의 흐름을 준비한다.
- 모델과 제공자는 응답 품질·지연·비용·데이터 처리 조건을 비교한 후 정한다.
- 학습 기반 음높이 추정 모델은 현재 알고리즘과 실제 녹음으로 비교할 필요가 생겼을 때 검토한다.

## 검증 기준

| 확인할 질문 | 검증 방법 |
| --- | --- |
| 측정값이 실제 입력을 반영하는가? | 알려진 기준음, 녹음, 소음·무음·불안정 입력을 비교하고 기기 정보를 기록 |
| 설명이 입력과 일치하는가? | 정답 음정·목표 불일치·신뢰도 부족·체감 불편 사례를 고정해 설명 검토 |
| 연습이 적절한 목록에서 선택되는가? | 과제 ID와 진행 조건 검증, 중단 조건에서 발성 과제를 제안하는지 확인 |
| 없는 곡 정보를 만들지 않는가? | 후보 ID·출처·입력 음역과 응답 비교, 정보 부족 시 미확인 처리 |
| 서비스 연결이 실패해도 연습을 이어갈 수 있는가? | 시간 초과·응답 오류 시 기본 피드백과 기록 보존 확인 |

수치 임계값과 모델 성능 목표는 실기기 기준 데이터를 모은 뒤 정한다. 현재의 자동 테스트 통과는 보컬 개선 효과를 검증한 결과가 아니다.
